--------------------------------------------------------------------------------
1. HOW DATA IS FETCHED & PROCESSED
--------------------------------------------------------------------------------

A. Upstream Data Sources:
   1. OpenAQ API v3 (Primary Ground Observation Provider)
      - Base URL: https://api.openaq.org/v3
      - Header: X-API-Key: <OPENAQ_API_KEY> (Backend only, never exposed to client)
      - Endpoint A: GET /locations?iso=IN&limit=100&page={page}
        -> Discovers registered physical monitoring stations, coordinates, and sensors.
      - Endpoint B: GET /locations/{location_id}/latest
        -> Fetches latest readings. Does not return parameter names directly;
           associated with location sensor metadata to resolve parameters and units.
      - Endpoint C: GET /sensors/{sensor_id}/hours?datetime_from=...&datetime_to=...
        -> Fetches hourly aggregated observations for 24h, 7d, and 30d trend lines.
      - Rate Limit Management:
        * Minimum 1050ms sequential pacing between requests to respect 60 req/min limit.
        * Controlled concurrency (max 3 simultaneous location syncs via p-limit).
        * Exponential backoff retry on transient 429 and 5xx responses.

   2. Open-Meteo Air Quality API (Forecast Provider)
      - Base URL: https://air-quality-api.open-meteo.com/v1/air-quality
      - Parameters: latitude, longitude, hourly=pm10,pm2_5,nitrogen_dioxide,sulphur_dioxide,carbon_monoxide,ozone,us_aqi,european_aqi, forecast_days=7
      - No key required. Completely separate from ground stations.
      - Labelled as "Modelled forecast" to avoid confusion with physical sensors.

B. Data Processing & Ingestion Lifecycle:
   - Ingestion Jobs (node-cron):
     * Location Sync (every 6 hours): Upserts stations and sensor arrays into MongoDB.
     * Latest Readings Sync (every 30 minutes): Fetches recent observations for monitoring stations.
   - Normalization Layer:
     * Transforms raw OpenAQ JSON into unified NormalizedObservation schema.
     * Standardizes pollutant identifiers ('pm25', 'pm10', 'no2', 'so2', 'co', 'o3', 'nh3').
     * Enforces strict unit validation (µg/m³ for particulates/gases, mg/m³ for CO).
     * Calculates observation age (ageMinutes = currentUtc - measurementUtc) and status:
       Recent (0–60 min), Delayed (1–3h), Possibly stale (3–6h), Stale (>6h).
   - Local CPCB AQI Calculation Engine:
     * Implements Central Pollution Control Board (CPCB) linear breakpoint interpolation.
     * Requires minimum 3 valid sub-indices including PM2.5 or PM10.
     * Requires at least 16 data points for a valid 24h average.
     * Determines overall AQI from the maximum sub-index (Dominant Pollutant).
     * Distinguishes calculated values with label: "BreatheBetter AQI — Calculated using CPCB methodology".
   - Standalone / Fixture Mode:
     * When MongoDB or OpenAQ credentials are unconfigured or offline, seamless in-memory fallback
       operates without crashing, serving authentic real-world Indian station datasets.
